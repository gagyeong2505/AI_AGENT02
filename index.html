CLI란 무엇인가

Command Line Interface는 텍스트 명령으로 프로그램을 직접 제어하는 방식입니다. Claude Code, GitHub CLI, Antigravity CLI처럼 각각의 도구를 명령어로 호출하고 결과를 다음 작업에 연결할 수 있습니다.

명령어 기본 구조 
[도구] [명령] [--옵션] [인수]

Claude Code

파일 편집, 코드 실행, MCP, Skill 실행을 담당합니다.

GitHub CLI

저장소, PR, 이슈를 터미널에서 관리합니다.

Antigravity CLI

터미널에서 Google Antigravity에 직접 질문합니다.

Claude Code CLI

  • + 자동화와 스크립팅에 적합
  • + Hooks, Skills, MCP 같은 고급 기능 지원
  • + 반복 작업과 파이프라인 연결에 강함
  • - 터미널 기본 지식이 필요하고 시각적 작업에는 불편할 수 있음

Claude Desktop

  • + GUI 기반이라 비개발자도 접근하기 쉬움
  • + Projects 단위 관리와 파일 드래그앤드롭에 편리
  • + CLI와 세션 공유 가능
  • - 고급 자동화 스크립팅과 파이프라인 연결에는 제한이 있음

ADV 02

웹 브라우저 자동화와 Playwright MCP

AI가 브라우저를 조작하는 원리를 이해하고, Playwright MCP로 웹 탐색·스크래핑·스크린샷·PPT 생성까지 이어지는 실습 흐름을 구성합니다.

Playwright

Microsoft에서 만든 브라우저 자동화 라이브러리입니다. Python과 JavaScript를 지원하고, 자동 대기 기능과 MCP 연동에 적합합니다.

MCP 방식

Claude가 MCP Tool을 호출하면 Playwright 서버가 브라우저와 통신하고, AI는 DOM 스냅샷을 텍스트로 받아 판단합니다.

Headless CLI

레코딩한 조작을 Python 스크립트로 바꾸고, 화면 없이 백그라운드에서 실행하는 자동화 환경까지 확장합니다.

웹 자동화 원리

코드가 브라우저를 직접 제어해 클릭, 입력, 데이터 추출을 자동 수행합니다. 새로운 프로젝트는 빠르고 설치가 간단하며 자동 대기를 제공하는 Playwright를 우선 사용합니다.

SETUP

GWS CLI 통합 설치 프롬프트

아래 흐름을 Claude에 요청하면 설치부터 OAuth 인증 준비까지 단계별로 진행합니다. OAuth 클라이언트 생성 단계에서는 Playwright MCP가 GCP Console 화면을 스냅샷으로 확인하며 안내합니다.

설치와 인증 순서

  1. 1. gws 설치`npm install -g @googleworkspace/cli`를 일반 터미널에서 실행합니다.
  2. 2. gcloud 인증`gcloud auth login --launch-browser`로 Google 계정 인증을 진행합니다.
  3. 3. GCP 프로젝트 설정프로젝트 생성 후 `gws auth setup`을 실행하고 Forms API까지 활성화합니다.
  4. 4. OAuth 클라이언트동의 화면, 테스트 사용자, 클라이언트 ID 생성 과정을 안내받습니다.
  5. 5. 환경 파일 저장`~/.config/gws/.env`에 인증 정보를 저장합니다.
  6. 6. 최종 스코프 인증6개 서비스 스코프를 묶어 `gws auth login`을 실행합니다.

NOTION DB

Notion은 AI 에이전트의 두뇌이자 저장소입니다

문서, 스프레드시트, 데이터베이스, 칸반을 하나의 공간에서 다루며 API로 AI가 직접 읽고 쓸 수 있습니다.

  • 문서 + 스프레드시트 + DB + 칸반을 하나로 사용합니다.

  • Trello처럼 상태별 칸반 운영도 가능합니다.

왜 Notion인가?

  • API 공개로 AI가 직접 읽고 쓸 수 있습니다.
  • 구조화 데이터와 서술형 문서를 함께 관리합니다.
  • 작업 지시부터 결과까지 한 공간에 남길 수 있습니다.

AI 연결 방식

  • Notion MCP로 대화 중 페이지를 직접 읽고 씁니다.
  • Notion DB에 작업 지시를 등록합니다.
  • Notion Docs에 보고서, 리서치, 콘텐츠 결과를 저장합니다.

단순 문서의 한계

  • AI가 조건에 맞는 항목을 골라내기 어렵습니다.
  • 상태 기반 자동화 파이프라인으로 연결하기 어렵습니다.

Notion DB의 강점

  • Status 필터로 AI가 `할일` 항목만 자동 조회합니다.

Notion MCP와 Notion API의 차이

대화 중 직접 연결할 때는 MCP가 편하지만, DB 필터와 자동화 스크립트는 API 방식이 더 적합합니다.

Notion MCP

  • Claude Code에 MCP 서버로 등록합니다.
  • 대화하면서 페이지 읽기와 쓰기가 가능합니다.

  • 제한: DB 필터 쿼리, 삭제, 일괄 수정 지원이 제한적입니다.

Notion API

  • Python 코드로 API를 직접 호출합니다.
  • DB 필터, 정렬, 페이지네이션을 자유롭게 사용합니다.
  • 데이터 생성, 수정, 삭제까지 자동화할 수 있습니다.
  • 이번 수업은 API 토큰 발급 → `notion-query` 스킬 제작 흐름으로 진행합니다.

Integration을 만들고 데이터베이스 페이지에 연결해야 API가 해당 DB에 접근할 수 있습니다.

  1. 1. `notion.so/my-integrations`에 접속합니다.

Integration 페이지 연결

  1. 1. 연결할 Notion 데이터베이스 페이지를 엽니다.
  2. 2. 우상단 `...` 메뉴를 클릭합니다.
  3. 3. Connections에서 만든 Integration 이름을 선택합니다.
  4. 4. Confirm을 클릭해 연결을 완료합니다.

DB ID는 URL의 `notion.so/workspace/[DB_ID]?v=...` 부분에서 복사합니다.

템플릿 복사와 세팅

  1. 1. 템플릿 선택`notion.com/templates`에서 Database 뷰가 있는 단순한 템플릿을 고릅니다.
  2. 2. Duplicate내 워크스페이스로 복사합니다.
  3. 3. 권한 연결앞서 만든 Integration을 Connections에 추가합니다.
  4. 4. DB ID 복사DB URL에서 ID를 확인해 Claude에게 전달할 준비를 합니다.

ADV 06

터미널에 남긴 한 줄 메모를 Claude가 트리거 키워드로 분류하고, Notion DB 4종에 자동 저장하는 시스템을 구축합니다.

기존 기록 방식

  • 노트앱, 메모앱, 할일앱이 각각 따로 흩어집니다.
  • 배운 내용, 할일, 아이디어를 다시 찾기 어렵습니다.
  • 기억이 파편화되어 자동화의 입력값으로 쓰기 어렵습니다.

이번 수업의 방식

  • 터미널에서 자연어로 한 줄만 입력합니다.

## 메모 분류 규칙

사용자가 메모를 입력하면 아래 규칙에 따라 분류하고 Notion에 저장한다:

- "개인:"으로 시작 -> notion-personal 스킬 실행 -> Personal Tasks DB 저장
- "업무:" 또는 "학교:"로 시작 -> notion-work 스킬 실행 -> Work Tasks DB 저장
- "메모:"로 시작 -> notion-notes 스킬 실행 -> Notes DB 저장
- "배움:"으로 시작 -> notion-docs 스킬 실행 -> Docs DB 저장

저장 완료 후 "저장됨: [DB명]" 한 줄만 출력한다.

ADV 07

Work DB의 오늘 할 일을 Claude가 조회하고, task 유형에 맞는 스킬을 순서대로 실행하며, Notion Status까지 직접 업데이트하는 에이전트 흐름을 완성합니다.

기존 방식

  • 캘린더, 조사, 시트, 이메일을 사람이 각각 요청합니다.
  • 스킬은 있어도 매번 어떤 스킬을 쓸지 직접 판단해야 합니다.
  • 작업 상태를 Notion에 다시 기록하는 일도 별도로 남습니다.

PM 에이전트 방식

  • Work DB에서 오늘 마감 task를 자동으로 조회합니다.
  • 유형을 읽고 미팅, 리서치, 문서, 이메일 스킬을 선택합니다.
  • 처리 전에는 진행중, 완료 후에는 완료로 Status를 바꿉니다.

'Work에서 오늘 처리해야 하는 것들 찾아서 처리해줘' 명령 수신 시:

4. 처리 완료 직후 Status = '완료' 변경
5. 오류 발생 시 메모에 '[오류] 사유' 기록 후 다음 task 진행

- 유형 = '리서치' -> work-research 스킬: 핵심 키워드 조사 후 결과를 메모에 저장

2. 분류

3. 업데이트

작업 전후 Status를 바꿔 Notion을 실시간 현황판으로 만듭니다.

work-meeting.md

  2. 2. 마감일은 오늘, Status는 시작 전으로 설정합니다.
  3. 3. 같은 명령을 다시 실행해 실제 캘린더, 메모, 시트, 이메일 결과를 확인합니다.

CASES

4가지 대표 케이스

PM 에이전트가 판단하는 기준은 단순합니다. Work DB의 유형 속성이 어떤 스킬을 호출할지 결정합니다.

케이스 1. 구글 캘린더 등록

유형이 미팅이면 task명에서 일정 정보를 파악해 Google Calendar에 등록하고 Status를 완료로 바꿉니다.

케이스 2. 데이터랩 조사

유형이 리서치이면 핵심 키워드를 추출해 검색량 추이를 확인하고 요약 결과를 Work DB 메모에 저장합니다.

케이스 3. 구글 시트 생성

유형이 문서이면 정리할 컬럼과 구조를 구성하고 Google Sheets 파일을 생성한 뒤 링크를 기록합니다.

케이스 4. 지메일 발송

유형이 이메일이면 수신자와 용건을 바탕으로 제목과 본문을 작성하고 Gmail로 발송까지 처리합니다.

완성 기준

Notion을 열어 둔 상태에서 Status가 시작 전에서 진행중, 완료로 바뀌고, 캘린더, 데이터랩 메모, 구글 시트, Gmail 결과물이 실제로 생성되면 7일차 PM 에이전트가 완성된 것입니다.

POLLING

폴링은 새 할 일을 기다리는 방식입니다

담당자 에이전트가 10초마다 Notion을 확인합니다. 내 이름이고 상태가 시작 전인 task를 발견하면 상태를 진행 중으로 바꾸고 실행합니다.

일상 비유

  • 10초마다 메모판을 확인합니다.
  • 새 메모가 없으면 다시 10초 대기합니다.
  • 내 업무 메모를 발견하면 즉시 처리합니다.

실제 동작

  1. 1. `notion_poller.py` 실행 후 10초 대기
  2. 2. Notion DB에서 내 이름 + 시작 전 task 조회
  3. 3. 새 task 발견 시 Status를 진행 중으로 변경
  4. 4. 스킬 호출, 산출물 생성, Status 완료 처리
  5. 5. 다시 대기 상태로 돌아가 반복

DEMO

담당자폴링 감지 후 각자 스킬 실행

API 키 준비

  1. 1. `platform.stability.ai` 접속 후 회원가입
  2. 2. Dashboard → API Keys → Create Key
  3. 3. `.env`에 `STABILITY_API_KEY=sk-xxx` 저장

Claude에게 요청할 내용

stability.ai API로 이미지 생성 스킬 만들어줘.
모델: sd3.5-flash
API 키: .env의 STABILITY_API_KEY
입력: 이미지 설명 텍스트, 한영 자동 번역 포함
출력: output/ 폴더에 PNG 저장
명령어: /image-gen [이미지 설명]
생성 파일: SKILL.md + generate.py

PRACTICE

실습 로드맵 7단계

이 순서대로 진행하면 Notion DB 상태 변화와 outputs 폴더 산출물을 통해 멀티 에이전트가 동작하는 것을 확인할 수 있습니다.

1. Notion 템플릿 복제

템플릿을 복제하고 Integration을 연결합니다.

2. .env 파일 설정

NOTION_TOKEN, REHEARSAL_DB_ID, STABILITY_API_KEY를 입력합니다.

3. 터미널 6개 실행

PM과 담당자 5명 폴더에서 각각 Claude를 실행합니다.

4. 폴링 시작

담당자 5명 터미널에 `폴링 시작`을 입력합니다.

5. 회의록 투입

PM 터미널에 Google Docs 링크를 전달합니다.

6. 자동 처리 관찰

상태가 시작 전, 진행 중, 완료로 바뀌는지 봅니다.

7. 결과 확인

Notion 메모 링크와 outputs 폴더 산출물을 확인합니다.

완성 기준

약 5분 안에 5개 산출물이 생성되고 Notion 상태가 모두 완료가 됩니다.
